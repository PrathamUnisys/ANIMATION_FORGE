# Technical Decisions

**Updated:** 2026-11-10 after live ComfyUI verification and the completed implementation.
The "Evidence / test" column now records what was actually executed, not only what was
planned.

| Decision | Alternatives considered | Evidence / test | Choice and trade-off | Replacement path |
|---|---|---|---|---|
| Module boundary | Extend current FastAPI/SQLite/React app; modify global schemas; self-contained module | Current ComfyUI adapter is DB-bound simulation; change control protects global schemas/runtime; existing tests have repo-wide write side effects | New `VISUAL_DEVELOPMENT/` package and local project folders. No database migration, existing route, protected schema, or frontend edits. The first review UI is a standalone local tool. Main-app integration requires a later approved CR. | Add authenticated API/routes and React panels only after an approved CR. |
| Project storage | SQLite tables; one mutable JSON; versioned folder artifacts | Need immutable reviewed artifacts and simple backup/inspection. Verified in the pilot: 26 generations produced, each with its own manifest and no overwrite | File-backed episode package: immutable inputs and output revisions, JSON manifests, append-only review events. No new database. | A repository can later implement the same storage interface. |
| Approved script gate | Any path supplied by caller; database lookup; signed external manifest | Only `SCR_PROJECT_001_V01` is APPROVED in the current DB; script text is immutable. Tested: the loader rejects `SCR_SCRIPT_LAB_10_V01` and unknown ids | CLI imports by database script ID using a read-only SQLite connection; rejects missing/non-APPROVED records; stores exact source text, approval state, revision, and SHA-256. Arbitrary files are not silently treated as approved. | Add a trusted approval-manifest adapter after governance/API approval. |
| Script analysis | One large LLM prompt; deterministic parser; parser plus optional provider | Existing screenplay headings and narrator script blocks are structured; the local LLM endpoint is unavailable. Live result: 3 sequences / 3 scenes / 9 shots, every source span slicing back to the exact screenplay text | Deterministic extraction of acts/scenes/speakers/action/narration plus evidence spans and explicit-vs-inferred labels. Do not invent story facts: Act III has no scene heading, so the parser records an open question and leaves location and time empty. | Add an optional structured provider behind an interface; validate every returned quote against the immutable source. |
| IDs | Random IDs; positional IDs; content-derived IDs | The first pilot run produced `SHT_001` in three sequences and failed the uniqueness check | Deterministic IDs derived from sequence and scene (`SHT_SCN_01_01_001`); every artifact also carries a source hash and analysis revision. A changed source creates a new analysis revision and visibly marks old outputs stale. | Human ID mapping tool for screenplay revisions. |
| Art-direction comparison | Independently prompted unrelated images; common scene and workflow | User requires meaningful comparison. Live result: 8 images from one scene at one seed; the graphic-novel and stylized-3D candidates render the same subject in clearly different language | 6-8 structured profiles, same scene, workflow, dimensions and seed; vary style dimensions in a recorded way. Human selects; the system never auto-approves. | Add curated profiles per genre after comparing real outputs. |
| Style continuity | Prompt text only; fixed model; optional reference conditioning | IP-Adapter paper shows text/image joint conditioning; ControlNet provides structural conditioning. Local inventory: **no** IP-Adapter model or node, **no** controlnet_aux, only the built-in `Canny` node and `control_v11p_sd15_canny.pth` | Global style rules are injected into each prompt; the Style Bible also carries the negative prompt and generation settings. Reference conditioning is limited to Canny ControlNet. Prompt consistency is treated as a cue, not a guarantee, and image identity is reported `NOT_CHECKED`. | Add model-specific IP-Adapter/LoRA/ControlNet workflow templates after live validation. |
| ComfyUI protocol | WebSocket-only; HTTP poll; external queue broker | Official routes expose prompt, queue, history, image view, uploads, and WebSocket progress. Live result: 26 generations completed through `/prompt` -> `/history/{id}` -> `/view` in 249 s total | Use HTTP queue submission and bounded polling of history/queue. Record each job and preserve raw response/errors. Easier to test locally and avoids an extra dependency. | Add WebSocket progress transport without changing job records. |
| Workflow configuration | Hard-code nodes/models; API JSON file plus explicit bindings; bundled UI workflows | The existing app adapter hard-codes false installed node/model lists. Live finding: the bundled workflows are UI-format files, and `sdxlturbo_example.json` references `sd_xl_turbo_1.0_fp16.safetensors`, which is not installed | Build API-format workflows in code with explicit node references and validate every node class and required input against the live `/object_info` **before** queueing. Two templates ship: `txt2img_v1` and `txt2img_canny_v1`. No model downloads. | Support multiple compatible templates and user-supplied workflow versions. |
| Blocking | AI image only; exact 3D scene generation; explicit 2D layout plus optional image generation | 2D image methods cannot establish calibrated world coordinates. Live result: the Canny-rendered blocking image kept the camera cone, sightline, subjects and props of the layout | Produce a deterministic normalized top-down SVG/PNG layout with subjects, props, camera, sightline, and movement. Optionally create a ComfyUI-rendered visual version tied to the same shot, using the layout PNG as the ControlNet image. Never claim Blender/Unreal world coordinates. | Add Blender scene/camera export only after a tested measured scale and coordinate convention exist. |
| Review UI | Modify Animation Forge React UI; static HTML; no UI | Existing UI work requires approved integration; images must be inspectable. Live result: HTTP 200 dashboard, 885 777 bytes of real PNG served, path traversal refused, approve/reject/regenerate recorded | Standalone local-only review page served by the module; image gallery, side-by-side candidate comparison, status, revisions, and decisions. Writes append-only local review events. | Port to React after formal change approval. |
| Continuity checks | Vision model score; prompt-text inspection; structured checks plus human review | No selected vision model or validated visual-identity metric in current environment. Live result: 6 PASS, 0 FAIL, 1 REVIEW, 1 NOT_CHECKED | Deterministic checks for IDs, style version, character/prop/location references, scene continuity flags, and manifest metadata; report image identity as NOT_CHECKED unless a human compares it. | Add a vision comparison provider after a benchmark and false-positive review. |
| 3D handoff | Emit exact Unreal/Blender coordinates; carry shot intent | Blender/Unreal tools can use camera transforms when authored, but generated image pixels are not 3D measurements | Export machine-readable shot specs and references, plus current SCENE/SHOT-compatible projections. Coordinate space and units remain unspecified: the package records `coordinate_space: NONE`, `world_coordinates: false`, `scale: UNSPECIFIED`. The `focal_length_mm` field is labelled a nominal planning equivalent of the shot size. | Add engine-specific exporters as separate adapters with real-file tests. |
| Prompt construction | One fixed paragraph template; per-workflow prompt strings; named modules | Comparing candidates and shots showed a single template entangles style, content and camera | Named modules (style, scene, environment, characters, action, objects, camera, composition, lighting, atmosphere, emphasis) assembled from the Style Bible plus the shot record. The structured shot spec is stored beside the final prompt in every manifest. | Add per-model prompt builders behind the same module keys. |
| Seed strategy | Fully random seeds; one seed for everything; per-shot deterministic seeds | A shared seed makes the candidate comparison attributable to style rather than noise; a per-shot deterministic seed keeps a shot reproducible while avoiding collisions between shots | Art-direction candidates share one seed. Storyboard and blocking use a seed derived from the base seed and the shot id. Regenerate deliberately advances the seed. | Allow per-shot seed overrides in the Style Bible scene variables. |
| Model choice | SDXL base; SD 1.5 `dreamshaper_8`; Flux2-Klein | Live inventory: `sd_xl_base_1.0.safetensors` (6.6 GB) is installed but heavy for an 8 GB card; `flux-2-klein-4b-fp8` needs the one-node pack and 3.9 GB of weights | Default to `dreamshaper_8.safetensors` with the optional `arcane_offset` LoRA at 0.65. Measured 8 s per 768x768 image. The model name is recorded in every manifest, so switching later keeps the provenance intact. | Add a Style Bible setting per checkpoint and benchmark SDXL before switching the default. |
