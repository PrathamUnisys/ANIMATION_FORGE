# Cross-Project Research Memory

Reuse prior findings as leads, not as current facts or authorization. Every memory item should include a stable identifier, project/context, candidate and exact version, claim, evidence URL/source type, retrieval date, host/test conditions, result, confidence, limitations, and review/expiry trigger.

Before reuse, re-check current official sources for pricing, license/terms, supported versions, APIs, security advisories, availability, and model restrictions. Revalidate hardware and workflow compatibility for the destination project. Distinguish transferable method/results from project-specific creative decisions, assets, credentials, data, and approvals. Do not copy secrets, private client data, or restricted inputs.

Store negative results and superseded claims with provenance. Preserve contradictions rather than overwriting history; mark stale evidence visibly and link replacements. Record which project and human reviewer accepted any reuse.

Cross-project memory never transfers toolchain approval, budget authorization, download permission, or approval of generated creative deliverables. The destination project's own R&D and human approval gates still apply.
